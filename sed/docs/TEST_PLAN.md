# sed — TEST PLAN

Run from the project directory:

```
python3 -m unittest discover -s tests -v
```

All tests are in `tests/test_ssed.py`, stdlib `unittest` only.
A helper runs `ssed.py` as a subprocess (stdin/stdout/argv, temp
files for `-i` and `w`), so tests exercise the real CLI, not just
imported functions.

## Coverage

1. Step 1 substitution: `s/\"//g` on the quotes fixture;
   first-occurrence-only (no `g`); `g`; alternate delimiters
   (`s|a|b|`, `s#a#b#g`); escaped delimiter (`s/\//X/g`);
   `&` whole match; `\1`/`\2` groups; unmatched group -> empty;
   numeric flag (2nd occurrence only); `i` flag; `p` flag
   (with and without `-n`); `w` flag file contents; empty
   pattern reuses last regex.
2. Step 2/3 addresses: `-n '2,4p'`; single line `3p`; `$p`;
   `/regex/p`; `/regex/i` address; range `2,4p`; range
   `/start/,/end/p`; range `2,/end/p`; range `/start/,$p`;
   range with end line number below start (single line);
   address on `s` and `d` commands, not just `p`.
3. Step 4 `G`: double-spacing, including on stdin.
4. Step 5 delete: `/^$/d` removes blank lines only; `2d`;
   range delete `2,3d`.
5. Step 6 `-i`: in-place substitution; `-i.bak` leaves a backup
   identical to the original; `-i` on multiple files; `-i`
   with stdin passes through (no crash, no file created).
6. Input handling: stdin (no file, `-` file), multiple files in
   order, line numbers reset per file, final line without a
   trailing newline stays without one, empty file, empty lines.
7. `q`: prints up to and including the addressed line, then stops.
   Verified against GNU sed 4.9: `2q` prints lines 1–2, while
   `-n 2q` prints nothing — `q` obeys `-n` (its print is just the
   normal end-of-cycle print, then processing stops). ssed
   implements `q` exactly that way.
8. Errors: unterminated `s`, unknown command, bad flag
   combination (`g` + number), address `0`, missing file
   (exit 2, other files still processed), missing script
   (usage error, exit 1), no script at all (usage error).
9. Byte-for-byte vs system sed: a dedicated test class runs the
   same script+input through both `ssed.py` and system `sed`
   and asserts identical stdout for every overlapping case
   (substitution variants, addresses, ranges, `G`, `d`, `p`,
   `-n`, `q`, stdin/files, no-trailing-newline input).
   Where GNU sed and ssed intentionally differ (regex dialect,
   error text, exit code for script errors is 1 in both), the
   comparison tests only cover stdout.

## Fixtures

- `tests/fixtures/quotes.txt`: 10 quote lines in the page's
  Step 0 shape (quoted lines), plus a blank line and a final
  line without a trailing newline in a second fixture
  (`tests/fixtures/edges.txt`) for terminator tests.
- Fixtures are generated by the test module's `setUp` into a
  temp dir where mutation is needed (`-i`, `w`); read-only
  cases use the checked-in fixtures directly.
